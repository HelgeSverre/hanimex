# Game-dependent latch banks

Branch: `submarine-latch-banks`, based on `submarine-sequential-blocks`.

This version recognizes 291 charge-storage latch cells and compiles 19 ordered
propagation programs around the horizontal timing block. Game-dependent gates
are evaluated from live chip state; their outcomes are not recorded or replayed.
The transistor engine and the inspector's 1,524-node interface remain available.

## Recognized circuit

`scripts/chip-latches.mjs` recognizes a narrow transistor topology:

- A storage node has no pull-up and exactly one channel connection.
- That connection is a single transfer transistor to a pulled-up source node.
- Every other transistor on the source connects it to ground: a NOR driver.
- Neither terminal is one of the externally driven console pins.

The transfer gate need not be a global clock. This covers game-controlled latches
as well as the two-phase banks, including stages in the 495–639 pipeline.
The generated cell describes both of its real nodes, not just a logical bit.

With the transfer gate off, the storage node holds its charge and the source
continues to evaluate its NOR inputs. With the gate on, the two nodes resolve
to the source value. The implementation preserves root-first update order,
including fanout events. It reads live ground-driver counts, so movement,
firing, mode changes and feedback remain part of the simulation.

Transfer connectivity is read directly from the gate bit. The solver no longer
maintains redundant bridge counts for these cells. Other transistor groups
still use the existing solver and connection counts.

## Bank compilation

The 86-node horizontal timing block from [the previous version](SEQUENTIAL-BLOCKS.md)
still supplies the clock phases and decoder outputs. Its compiler now removes
closing-transfer events for recognized cells: disconnection itself changes
neither the held charge nor the independently driven source. Changes to a source's
NOR inputs still schedule that source normally. This omission is restricted to
the compiled timing transition; startup and other drives retain normal settling.

The remaining initial propagation sequences reduce to 19 programs. Each program
emits calls with constant node IDs in the original queue order. Rust can
specialize the latch operations and array accesses without a per-node indirect
call. Events generated by those calls then use the usual ordered work queues.
The first program counts toward the existing 100-pass settling limit.
Release builds inline the constant-node operations; debug builds keep normal
calls so the generated programs do not exhaust the test thread stack.

All writes go to the same node array used for raster output and inspection.
There is no separate inspector reconstruction or approximate animation.

## Checks

```sh
npm run build:chip
cargo test --manifest-path crates/ay38605/Cargo.toml
cargo clippy --all-targets --all-features --manifest-path crates/ay38605/Cargo.toml -- -D warnings
npm test
npm run test:edges
npm run test:games
```

The cell test exhaustively checks **303,328 input, charge and root-order
combinations** against a raw transistor-channel walk. The circuit test covers
reset, disable/re-enable, selection pins, fire inputs and repeated clock levels.
The Wasm edge comparison checks every node across 200,000 half-clock edges,
including changing controls and resets.

`test:games` runs six independent comparisons concurrently, one for each game
selection. Each runs 256 fields with changing controls and fire/skill pins,
covering **109,264,896 clocks** in total. Every 2,048 clocks it compares all nodes,
all raw raster samples and the field count. Unlike the earlier long check,
each selection runs past the startup movement-inhibit period. All six passed:
**109,264,896 clocks and 53,352 checkpoints**, with no node, raster or field-count
differences.

These are comparisons with the recovered simulation model. Physical-console
validation, analog sound and original color decoding remain unfinished.

## Performance

The final benchmark measured **855,344 clocks/s**, compared with 388,155 for
the previous engine and 86,740 for the transistor reference. That is **2.20×
the previous version**, **9.86× the reference**, and **23.90% of hardware speed**.
Full speed has not been reached.

The paired measurements and binary hashes are in
[latch-benchmark.json](latch-benchmark.json). The benchmark gives each instance
100,000 warm-up clocks before timing another 100,000, alternating engine order
across four trials. The compiled Wasm is 1.57 MB (211 KB gzip), up from 1.40 MB (107 KB gzip).
The larger generated functions need this warm-up to avoid
mixing first-use Wasm compilation with steady-state execution.

To compare against the previous branch:

```sh
mkdir -p work
git show 2682c99:web/src/chip/ay38605.wasm > work/sequential-baseline.wasm
node scripts/benchmark-chip.mjs --baseline=work/sequential-baseline.wasm
```

Full speed is **3,579,545 clocks/s**. Browser throughput is lower than a tight
Wasm benchmark because it includes worker scheduling and rendering.

Generic truth tables and per-cell Boolean functions matched the reference but
were slower. A separate attempt to dispatch every remaining node through its
own compiled function was also slower. Those paths were discarded.

The remaining work is concentrated in subsequent propagation passes and fanout
bookkeeping. Further compilation needs to preserve phase ordering and charged
nodes across game feedback; simply advancing a gameplay counter would not do so.

## Inspector

The header's **Chip** button opens the inspector and shows measured speed.
Engine selection now lives beside the inspector's video and stepping controls.
Switching engines resets the cartridge and reopens the inspector. Keyboard
navigation, native dialog dismissal, signal selection and half-clock stepping
remain available. The TV is no longer covered by the engine controls.
